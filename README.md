ランダムに現れるプロ野球選手を「取る」か「見送る」かだけで、最強の9人を作るブラウザゲーム。

**遊ぶ → `index.html` をブラウザで開く**

---

## どんなゲームか

### ① 選手を集める（10人）

- 選手はポジション関係なく **完全ランダム** で1人ずつ登場する
- できる操作は「**取る**」「**見送る**」だけ
- 集めるのは **投手1人＋野手9人 = 10人**（DH制を前提にした構成）
- **投手は1人だけ**。1人取ったら、それ以降は通常の投手が出てこない
- **二刀流選手**は「投手として取る／野手として取る」を選べる
  （`data/twoway.tsv` に書いた選手。出やすさの特別扱いはしていない）
- 「見送る」は **5回まで**。さらに **残り2人になったら見送れない**
- 最後の1枠で投手が0人なら、**必ず投手か二刀流が出る**（詰まないようにするため）

捕手が最後まで来ない。ショートがいない。投手が最後まで出ない。
**「10人集めること自体が難しい」** ことがこのゲームの面白さです。

### ② 集めたあと、2つの道に分かれる

| 道 | 内容 |
|---|---|
| **スタメンを組む** | 打順と守備位置を決めて、チーム評価（★と点数）を見る |
| **投手を補充してシーズン開始** | 投手を足して **143試合** を戦い、成績と順位を見る |

シーズンでは、
リーグ（セ／パ）を選び、投手の役割（先発・中継ぎ・セットアッパー・抑え）を決めて開幕。
打撃成績・投球成績・順位表を見て、3位以内なら **クライマックスシリーズ**、
勝ち抜けば **日本シリーズ** へ進みます。

最後に結果画像とXシェア用の文章、他の人に見せられる結果URLを作ります。

## 技術構成

- **HTML / CSS / JavaScript のみ**。フレームワークもビルドも不要
- 外部ライブラリは **ゼロ**（結果画像も canvas に自力で描いている）
- 選手データは `data/` と `js/players-data.js` に分離
- サーバー不要。GitHub Pages などの静的ホスティングだけで動く

## ローカルでの動かし方

`index.html` をダブルクリックしても動きますが、
ブラウザによっては制限がかかるので、簡易サーバー経由をおすすめします。

```bash
# このフォルダの中で実行
python3 -m http.server 8000
```

実行後、ブラウザで http://localhost:8000 を開く。止めるときは `Ctrl + C`。

## 選手データについて

### データの出どころ

成績は **NPB公式（[npb.jp](https://npb.jp/bis/2026/stats/)）が公開している個人成績**
（2005〜2026年の規定到達者）をそのまま使っています。

```bash
# 成績を最新にする（年度を指定）
node tools/fetch-npb.js 2026

# 取ってきた成績をゲーム用データに変換する
node tools/build-players.js
```

`build-players.js` を実行すると `js/players-data.js` が作り直されます。
このファイルは自動生成なので直接編集しないでください。

### 二刀流選手は `data/twoway.tsv` で定義する

NPB公式の成績は「規定到達者」だけなので、二刀流選手の投打が両方そろいません。
そこで `data/twoway.tsv` に、投打の成績をまとめて書きます。

```
選手名	年度	チーム	野手ポジション	打席	打率	本塁打	打点	出塁率	長打率	登板	投球回	勝	敗	防御率	奪三振
大谷 翔平	2016	日本ハム	右	382	.322	22	67	.416	.588	21	140	10	4	1.86	174
```

ここに書いた「選手名＋年度」は、通常の投手データより優先されます
（同じ選手が投手カードと二刀流カードで二重に出ることはありません）。

**空欄があるとその行は読み飛ばされます。**
実在の選手に想像で埋めた数字を付けないための作りです。
`node tools/build-players.js` を実行すると、足りない項目を名指しで教えてくれます。

### 年齢は `data/ages.tsv` で補える

NPB公式の個人成績には生年月日が入っていません。
年齢はシーズンの成績予測（若手の成長／ベテランの衰え）に使うので、
正確に扱いたい選手は `data/ages.tsv` に生まれた年を書いてください。

書いていない選手は「データに初めて出てきた年に23歳だった」と仮定して推定します。
データのいちばん古い年（2005年）から載っている選手は推定できないので、
年齢不明として扱い、28歳相当で計算します。

### 守備位置は別ファイルで管理している

NPB公式の個人成績には守備位置が含まれていません。
そのため「誰がどこを守る人か」は `data/positions.tsv` で持っています。

```
選手名	主ポジション
佐藤 輝明	三
中野 拓夢	遊
```

- 使えるポジション記号： `投 捕 一 二 三 遊 左 中 右`
- 投手成績に載っている選手は自動で「投」になるので、書かなくてよい
- ここに載っていない野手は **ゲームに登場しません**（間違ったデータを出さないため）
- 直したら `node tools/build-players.js` を実行すると反映される

### 権利について（公開する前に読んでください）

このゲームは **公開して問題ないものだけ** で作っています。

| 使っているもの | 扱い |
|---|---|
| 選手名・球団名・成績 | NPB公式が公開している事実データ。出典をページに明記 |
| 選手写真 | **使っていない**。選手ごとに色が決まるシルエットをコードで描画 |
| 球団ロゴ・球団マーク | **使っていない** |
| 球団のカラーリング・商標 | **使っていない**。守備位置ごとの独自配色 |

「打撃力」「長打力」「走力」「守備力」「投手力」「守備適性」は
**本ゲーム独自の指標**で、NPBの公式評価ではありません。
画面にもその旨を明記しています。

> 実在選手の写真や球団ロゴは、著作権・肖像権・商標の対象です。
> 個人開発で許諾を得るのは現実的ではないため、最初から使わない設計にしています。

## 調整したくなったら

| やりたいこと | 直すファイル |
|---|---|
| 見送れる回数を変える | `js/config.js` の `PASS_LIMIT` |
| 集める人数・投手の枠を変える | `js/config.js` の `TEAM_SIZE` / `PITCHER_SLOTS` / `FIELDER_SLOTS` |
| 「残り何人で見送り禁止」を変える | `js/config.js` の `FORCE_PICK_WHEN_REMAINING` |
| 投手が出すぎる／出なさすぎる | `js/config.js` の `POSITION_WEIGHTS` |
| 試合数・補充できる投手の数 | `js/config.js` の `SEASON_GAMES` / `PITCHER_ROSTER` |
| 「どこなら守れるか」を変える | `js/positions.js` の `FIT_TABLE` |
| 点数の付け方・★の基準を変える | `js/evaluate.js` の `WEIGHTS` / `CURVE` / `STAR_STEPS` |
| 評価コメントを増やす | `js/evaluate.js` の `RULES` / `FALLBACK` |
| シーズンの成績予測を変える | `js/season.js` の `TUNE` |
| ライバル6球団の強さを変える | `js/season.js` の `TUNE.RIVAL_RS` / `RIVAL_RA` |
| 選手を追加する | `data/positions.tsv` に追記 → `node tools/build-players.js` |

評価ロジックは `js/evaluate.js`、シーズンの計算は `js/season.js` だけで完結しています。
この2つのファイルには画面表示やゲーム進行のコードを入れないでください。

## シーズンの成績はどうやって作っているか

完全なサイコロではありません。土台は **その選手が実際に残した成績** です。
そこに次を足して、今シーズンの数字を作ります。

```
実際の成績（OPS・防御率など）
  ＋ 年齢による伸び／衰え     … 27〜28歳がピーク。若いほど伸びしろ、34歳以上は急に落ちることも
  ＋ キャリア年数             … プロ入り3年目までは「覚醒」が起きやすい
  ＋ そのシーズンの調子       … ここだけランダム（つりがね型の乱数）
```

数字どうしが矛盾しないよう、打率・出塁率・長打率・本塁打・打点は
**お互いから逆算して**作っています（例：出塁率と打率から四球の数を出す）。
打てない年は出番そのものが減るので、「打率1割台で規定打席」は起きません。

チームの強さは、打線の wRC+ と投手陣の防御率から
**1試合あたりの得点と失点**を見積もり、そこから勝率を計算します（ピタゴラス勝率）。
登録した10人の投手だけでは1年ぶんのイニングを投げきれないので、
足りないぶんは「その他の投手」が投げたものとして失点に加えています。

ライバル6球団の強さは、**同じやり方で組んだチームの平均**に合わせてあります。
そのため、ふつうに組めば5割前後、うまく組めば上位に行けます。

自分のリーグ（自分＋6球団＝7チーム）と、もう一方のリーグ（6球団）の
**両方**を同時に動かしています。交流戦は実際にその2リーグの間で戦わせ、
日本シリーズの相手はもう一方のリーグを勝ち抜いた実在の球団です。

## 結果の共有について

- **Xシェア** … X の公式シェアURL（`twitter.com/intent/tweet`）を開くだけです。
  X API は使わないので、勝手に投稿されることはありません。投稿するかは本人が決めます。
- **結果URL** … サーバーを使わず、9人の選手IDと守備位置を圧縮して
  `result.html?d=...` に埋め込んでいます。データベースは不要です。
  将来 `/result/abc123` のような短いURLにしたい場合は、
  `js/share.js` の `ShareCode` を差し替えれば対応できます。

## 不正対策について

ブラウザだけで動くゲームなので、**完全に防ぐことはできません**（詳しい人なら書き換えられます）。
初期版では、個人情報を取らないシンプルな設計を優先して、次の軽い対策だけ入れています。

- 保存データと結果URLに**チェックサム**を付け、書き換えられていたら読み捨てる
- `js/players-data.js` に無い選手IDが入っていたら無効にする
- 守備位置が重複している結果URLは表示しない

---

## 広告について

初期版では広告を出しません（`js/config.js` の `ADS_ENABLED` が `false`）。
トップ・ゲーム開始前・結果画面に `<div class="ad-slot">` の枠だけ用意してあります。
広告を入れるときは `ADS_ENABLED` を `true` にして、`js/ads.js` の
`renderSlot()` に広告タグを書きます。

※ 広告を入れる場合は、プライバシーポリシーのページが別途必要になります。
